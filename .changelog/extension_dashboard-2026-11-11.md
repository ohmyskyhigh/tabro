# Extension dashboard

## Objective

Build a dashboard opened from the Tabro extension. Show pairing code, alias and connection status on one tab, and Broker profiles and domain rules on another. The user clarified that profiles and status must be read-only in this version.

Follow-up: correct the persistent Connecting label and make background operation a soft preference, allowing explicit activation when a website needs it.

## Changes

Replaced the existing options page with Connection and Broker management tabs, responsive tables, keyboard tab navigation, pairing/reconnect controls and confirmed pairing reset. Added domain rule add/edit/remove and removal confirmation, validation, conflict feedback and retained drafts. Management requests use the authenticated extension relay with generation-bound correlation; only the extension options page can invoke them. The Broker exposes profile snapshots and validated revision-checked rule replacement. Saves refuse invalid, stale or oversized configurations before atomic replacement; dashboard support is negotiated with compatible relay peers. No profile lifecycle commands, generic MCP execution surface or new MCP tool was added.

Updated the approved proposal/plan and canonical Product, UX, UI, System, Component and File documents. Updated both READMEs and setup guidance. Added dashboard service, rule persistence and authenticated relay tests, and an opt-in real extension-page probe in the existing packaged installation suite. The release matrix enables that probe for Windows, both macOS architectures and Linux; those remote jobs have not been run here. Test actions use Chrome input commands; website enforcement is checked through the actual MCP → Broker → Native companion → extension path.

The focus/status follow-up defaults Broker-created workspace, additional and replacement tabs to inactive, with an inactive extension fallback. Explicit `Page.bringToFront` remains available, including on input-only domains; MCP descriptions and the Hermes browser workflow advise background work and avoiding repeated activation. The dashboard now presents Connection and Automation separately, with a visible timeout diagnostic instead of inferring Connecting from a running Chrome process. No new foreground restriction, approval gate, MCP field or configuration flag was added. Existing held-input recovery remains intact.

Cleanup exposed a deadlock: acknowledged released input still prevented termination, while resuming required resolution of the unknown website effect first. Explicit termination now accepts confirmed release only for its owning workspace/session and abandons confirmation-waiting commands as failed with possible effects retained. It keeps input recovery until archival succeeds and never replays input or creates replacement tabs. Added a regression covering refusal before acknowledgement, successful termination afterward, schema-valid failure facts and durable possible-effect history. Updated the canonical documents, plan/proposal, MCP description and Hermes guidance.
