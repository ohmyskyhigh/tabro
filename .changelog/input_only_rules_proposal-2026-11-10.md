# Input-only domain rule proposal

## Objective

Record the reviewed domain-rule design in the existing source-of-truth vault, then implement the approved rule list, MCP guidance, guarded observation and interrupted-input recovery.

## Changes

Confirmed the existing authority hierarchy and approval workflow in `doc/TOP-DOWN-MOC.md` and `doc/AGENTS.md`. Added the [domain-rule proposal](../doc/90-Proposals/domain-input-only-rules-2026-11-10.md), its [implementation plan](../doc/80-Plans/domain-input-only-rules-2026-11-10/README.md), and entries in both indexes. The proposal records confirmed user direction, recommended defaults, review findings, local Chrome probe evidence and outstanding operator-facing decisions.

The follow-up review added a six-gap closure checklist with required acceptance evidence. Concrete proposed defaults now cover initial configuration, subdomains, navigation, Unicode input, handoffs, held-input coordination and interruption recovery. Actual domain names remain deployment input.

The user clarified domain scope. Each hostname entry covers all nested subdomains and every URL path automatically. Matching uses the tab's current top-level URL, so navigation to listed B applies B's rule and navigation from listed A to unlisted B restores standard behavior. Updated the proposal, configuration example, delivery steps and acceptance cases accordingly. Iframe-specific matching and redirect-history tracking are excluded from the requested scope.

Updated interrupted-gesture recovery after user review. Track intended and confirmed input, reconcile lost acknowledgements, and use the thirty-second inactivity timeout to pause affected-window manipulation. Recovery uses observations and explicit acknowledgement when needed. Automatic recovery emits no release or repeated gesture. The plan now includes the required recovery-read exception to same-tab FIFO, diagnostics, resume-contract changes and tests for restart and interruption boundaries.

On 2026-11-11, expanded the testing strategy around interrupted gestures and domain enforcement. Added explicit invariants, deterministic dispatch/execution/cache/response failure cases, timer boundaries, durable restart checks, guarded recovery reads and separate resume gates. Assigned checks to existing suites and one planned real-browser suite. Defined fixture event/DOM/effect evidence, native platform and actual Codex/Hermes acceptance, isolated host setup, and release gates that reject skipped qualification. Updated the proposal to distinguish planned acceptance from the earlier limited Chrome probe.

On 2026-11-11, the user approved implementation. Promoted the decision through Product, User Experience, User Interface, System, Components and Files; accepted the proposal and updated the plan's delivery evidence. Added validated live `browser-rules.json` loading, authenticated policy revisions and extension capability negotiation, current-top-level-domain matching, guarded script observation, explicit CDP classification and actionable policy errors. Added SQLite migration 009 for rule initialization and durable held input. Input intent and confirmed outcomes persist atomically with attempts; recovery observes without replay/release, preserves uncertain effects, and requires the appropriate user acknowledgement. Authorized takeover transfers recovery responsibility without discarding held input. Contract 6 retains the twenty-two-tool catalog and adds policy/recovery facts and resume acknowledgement.

Updated English/Chinese README and setup guidance, Hermes browser and LinkedIn workflows, protocol/schema gates and existing tests. Added focused policy tests and one packaged real-Chrome recovery suite. Release CI now runs that suite for every supported platform and checks its passing evidence report, keeping diagnostic artifacts separate from release assets. Native installation tests now assert rules are initialized and preserved across setup/update. Isolated fixture profiles retain Chrome's security sandbox and do not register a replacement Native Messaging host.

## Result

Implementation and canonical documentation are complete in this checkout. `pnpm verify` passes lint, TypeScript checking, 294 non-E2E tests, two simulated multi-client E2E tests and the macOS host build; 21 environment-gated tests are explicitly skipped by ordinary verification. The separate macOS arm64 packaged Chrome test passes supported gestures, forbidden scripted effects, lost-release reconciliation, a real Broker process crash, guarded recovery reads, explicit acknowledgement and a real thirty-second modifier timeout. Its evidence is `artifacts/qualification/darwin-arm64-input-only.json`.

Windows x64, macOS x64 and Linux x64 qualification, installer preservation qualification on those other targets, the remaining exhaustive interruption cases and actual Codex/Hermes application/agent acceptance remain release gates in the implementation plan. MCP SDK sessions under both identities are not claimed as actual client acceptance. Source and a local staged package were updated; no commit, push, public release, live installation replacement or historical Hermes-runtime regeneration was performed.

On the user's request to test a website on this machine, ran the packaged installer on the host into an isolated macOS install root and Chrome user-data directory. The unmodified extension connected through Native companion. Extended the existing portable installation test with an opt-in Selenium public-form exercise and retained command reports and screenshots. Scripted click/value assignment were rejected with unchanged controls; pointer/keyboard input filled Unicode text and a textarea, checked controls, selected Two and submitted the demo form to Received. Repeated setup and Broker restart preserved the rule list, and both user-owned and Broker-owned profiles completed browser actions. The final native/public-site test passed in 39.55 seconds; the separate real-Chrome interruption suite passed again in 58.11 seconds.
